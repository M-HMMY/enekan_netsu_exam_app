# 章を書かせるプロンプトの本体

**章ごとの指示（`10-【章 ID】.md`）は、この文書と `00-common.md` を読ませたうえで、その章だけの表と釘を渡します。**
この文書に共通の手順が書いてあります。

**章ごとの指示だけを渡さないでください。**下をこの順に読ませること。

1. `CLAUDE.md`
2. `scripts/prompts/00-common.md`
3. `scripts/prompts/01-chapter.md`（この文書）
4. `scripts/prompts/10-【章 ID】.md`（担当章の指示）

**★ 2026 年 9 月 30 日に、エネルギー管理士（熱分野）向けに書き直しました。**

---

## 手順

### 1. 読む

| ファイル | 何のために |
| --- | --- |
| `CLAUDE.md` | このアプリの前提。とくに「確認問題の形」と「公開のルール」 |
| `scripts/prompts/00-common.md` | 読者像・出題の形・記法・リンクしてよい節 ID・名指しの釘 |
| **`src/data/textbook/intro.ts`** | **★ 文体の見本。**書き始める前に 4 節とも読むこと |
| `docs/section-plan.md` | 節の割り方。**§3 の「課目をまたぐテーマの置き場所」**を必ず見ること |
| `docs/syllabus.md` | 出題範囲。担当章の表の【出題】【推定】の印を見ること |
| `docs/public-questions.md` | 令和 6〜8 年度に実際に問われた形（§3・§4）と、記述の正誤（§7） |
| `docs/primary-numbers.md` | **法令の数値の台帳。ここに無い法令の数値を書かないこと** |
| `src/types.ts` | `TextbookSection` の型 |

**★ `src/data/textbook/intro.ts` は必ず読んでください。**文体・密度・表の使い方・一問一答の書き方を、そこに合わせます。

### 2. 材料を確かめる

**★ 公開問題の記述を材料に使うなら、`docs/public-questions.md` §7 で正誤を確かめること。**

この試験には、**記述の組合せを選ぶ空欄**と、**誤った記述を 2 つ選ぶ空欄**があります。
つまり**公開問題に出ていた記述の一部は、誤りの記述**です。「令和 N 年度に出ていた」だけでは、正しい側か誤りの側かは決まりません。

**★ 高圧ガス甲種版で、この照合を飛ばして誤りの記述を 6 か所、正しいものとして書きかけました。**どれも、もっともらしく読めます。試験がそう作ってあるからです。

**`§7 の「誤」の行を、正しい説明として書かないでください。**§7 は標準解答の記号から正誤を決めたもので、信頼できます。

**法令の章（`k1-law`）**は、台帳（`docs/primary-numbers.md`）に写してある条文の数値だけを使ってください。
条文そのものは、scratchpad に書き出したものではなく、**e-Gov で令和 8 年 4 月 1 日時点の版**を見ること（取り方は台帳の §0）。

### 3. 書く

**`src/data/textbook/【章 ID】.ts` だけ**を書いてください。**他のファイルは絶対に変更しないでください。**
（`src/data/textbook/index.ts` への登録は、依頼した側が行います。）

```ts
import type { TextbookSection } from '../../types';

export const 【章 ID をキャメルケースにしたもの】: TextbookSection[] = [
  {
    id: 'tf-1',
    categoryId: 'k2-gas',
    title: '…',
    goal: '…',
    minutes: 12,
    body: `
# ざっくり言うと

…
`,
  },
];
```

- **`id` と `title` は、章ごとの指示で渡したものをそのまま使うこと。**勝手な ID を作らないでください
- **`goal` は「〜できる」で終わる 1 文。**一覧に出ます
- **`minutes` は 10〜15**
- **`body` の先頭は改行から**（テンプレートリテラルの書き出し）
- キャメルケースの例：`k2-gas` → `k2Gas`、`k4-hx` → `k4Hx`

### 4. 報告する

`00-common.md` §11 の形で報告してください。

## 節の骨格（**崩すと直前チェックシートに載りません**）

```
# ざっくり言うと          ← 日常語で「何の話か」。2〜4 段落
（本論。見出し・表・図）
> **試験のポイント** …     ← 1 節に 1〜2 個
> **よくある勘違い** …     ← 1 節に 1〜2 個
# この節のまとめ           ← 箇条書き 5〜6 個
```quiz                    ← 一問一答。5 問以上
問い :: 答え
```
```

**「# ざっくり言うと」「# この節のまとめ」「> **試験のポイント**」「> **よくある勘違い**」は、この文字列そのもので書くこと。**
`src/lib/digest.ts` が機械的に抜き出します。**崩すと黙って拾われません。**

---

## ★ 「ざっくり言うと」の書き方

**ここが読まれるかどうかを決めます。**

- **日常語で書く。**記号や法令用語をここで使わない
- **読者の現場の経験に接ぎ木する。**「ボイラの運転記録には、給水量と燃料の使用量が並んでいますね。この節は、その 2 つからボイラの効率を出す話です」
- **この節を読むと何ができるようになるかを、1 文で言う**
- **2〜4 段落。**長くしない

**悪い例**（定義から始めている）。

> 熱力学第一法則は、閉じた系において内部エネルギーの変化が、系に加えられた熱量から系が外部にした仕事を引いたものに等しいことを述べる法則です。

**良い例**（現場から入る）。

> やかんに火をかけると、水は温まり、ふたが持ち上がります。加えた熱は、温めるほうと押し上げるほうに分かれて使われました。
> **この「分かれ方の帳尻」を式にしたものが、熱力学第一法則です。**課目Ⅱの計算は、ほぼすべてここから始まります。

## ★ 「よくある勘違い」の作り方

**読者は、現場で設備を見てきた技術者です。いちばん危ないのは「知らないこと」ではなく「知っているつもり」です。**

**次の型から作ってください。**

| 型 | 例 |
| --- | --- |
| **現場の言い方と、試験の定義のずれ** | 「ボイラ効率」を燃料の高発熱量で割るか低発熱量で割るか。「蒸気の圧力」がゲージ圧か絶対圧か |
| **似た量の取り違え** | 温度効率とエネルギー効率と有効度 ε。理論空気量と実際の空気量。有効電力と皮相電力 |
| **比例の向きと次数の取り違え** | 層流と乱流で、圧力損失が流速の何乗に比例するか。放射が温度の何乗に比例するか |
| **法の数え方を現場の感覚で推測する** | 「使ったエネルギーは全部足す」「非化石なら 3.60」（`00-common.md` §2 の表） |
| **公開問題で「誤」だった記述** | `docs/public-questions.md` §7 の誤りの記述。**なぜ誤りかを仕組みから説明する**（記述を写さないこと） |

## 表を使うところ

- **比較するもの**（拡散燃焼と予混合燃焼、丸ボイラと水管ボイラ、衝動タービンと反動タービン、P・I・D の各動作）
- **状態変化・サイクルの一覧**（何が一定で、仕事・熱量・内部エネルギーの変化がどうなるか）
- **数値の一覧**（法令の閾値・人数・換算係数。**台帳の値だけ**）

## 図

**図は自前の実装です。**使えるのは次の 8 種類だけです。

| 種類 | 何に使うか |
| --- | --- |
| `flow` | 手順や流れ（使用量を集める → 原油換算 → 指定区分 → 選任、蒸気の流れ） |
| `stack` | 積み重なる構造（法 → 令 → 則 → 告示） |
| `tree` | 分類（燃焼方式の分け方、熱交換器の形式） |
| `matrix` | **2 × 2 の 4 セルまで。**5 個目以降は黙って捨てられます |
| `cycle` | 繰り返し（冷凍サイクルの 4 つの機器、ランキンサイクル） |
| `seq` | やりとり（届出と受理）。**`A -> B :: 内容` の形。矢印がないと右が消えます** |
| `bits` | ビット列（この試験ではまず使いません） |
| `compare` | 左右の対比。**1 行 1 セル、偶数行が左・奇数行が右。`::` は左右の区切りではありません** |

**★ 図の中で `**強調**` は効きません。**アスタリスクがそのまま出ます。
**★ T-s 線図や P-h 線図は、この図の仕組みでは描けません。**線図を読む節では、**状態点の並びと、各過程で何が一定かを表で示し**、線図の形は文で説明してください。

**無理に図を入れないでください。**表のほうが伝わるなら表にすること。

## 一問一答（quiz）

- **1 節に 5 問以上**
- **答えは言い切る。**「〜など」で濁さない
- **「〜とは何か」より「〜はいくつか」「どちらが大きいか」「何乗に比例するか」**のほうが効きます

**良い例。**

```
層流で、管摩擦による圧力損失は平均流速の何乗に比例するか :: 1 乗です（乱流で完全粗面なら 2 乗）
原油換算で 1 GJ は何 kL か :: 0.0258 kL です
エネルギー管理者に選任できるのは誰か :: エネルギー管理士免状の交付を受けている者です
```

## 章ごとの指示（`10-【章 ID】.md`）の形

**依頼する側が、章を書かせる直前に `docs/section-plan.md` と `docs/syllabus.md` から起こします。**次の 6 つを入れること。

1. **担当章と節の表**（`section-plan.md` §5 の該当部分をそのまま）
2. **令和 6〜8 年度にその大問で問われたこと**（`public-questions.md` §3・§4 の該当行。見出しの語だけ）
3. **§7 の「誤」の記述のうち、その章に関わるもの**
4. **課目をまたぐテーマの置き場所**（`section-plan.md` §3 のうち、その章が本体の側か参照する側か）
5. **埋め込む体験ウィジェット**（あれば）
6. **その章だけの釘**（`syllabus.md` の【推定】の項目をどこまで書くか、台帳に無い数値をどう扱うか）

## ★ やってはいけないこと

1. **公開問題の原文を写さない**（省エネルギーセンターが無断の複製・転写を禁じています。`00-common.md` §10）
2. **指定されたファイル以外を変更しない**
3. **`npm run check` を実行しない**（並行実行でキャッシュが衝突します）
4. **節 ID を勝手に作らない**
5. **台帳に無い法令の数値を書かない**
6. **「事実に自信がない箇所はありません」と報告しない**
7. **本体でない側の節に、同じ説明を書き直さない**（リンクで参照する。`section-plan.md` §3）
8. **bash のヒアドキュメントを使わない**（バックスラッシュを落とします）
