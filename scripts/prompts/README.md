## 回し方

**1 章ごとに、この順で回します**（`docs/next-session.md` にいまの進み具合）。

1. **書かせる** … 書き手のサブエージェントに `02-dispatch.md` の依頼文（教本）か `80-questions.md`（確認問題）を渡す
2. **登録する** … `src/data/textbook/index.ts`・`src/data/questions/index.ts`・`passages.ts` へは**依頼した側が**足す
3. **検査する** … `npx tsc --noEmit`、`npm run check`、`npm run build`。字数は `npm run dump <節 id>`
4. **コミットする**
5. **別の目のレビュー** … **書いた本人とは別のサブエージェント**を新しい文脈で起こし、**ファイルを書き換えない役割で**
   `90`（教本）・`91`（確認問題）・`92`（ドリル・ウィジェット）を渡す
6. **直す** … 指摘を修正役のサブエージェントに渡す。**直したら `93`（2 巡目）を掛ける**
7. **push して、公開ページの `index-*.js` の名前が手元の `dist/` と一致するかで反映を確かめる**

### 守ること

- **同時に走らせるのは 4 本まで。**5 本で利用上限に当たった。4 本でも当たることがある。
  止まったら、**そのエージェントに SendMessage で続きを頼む**（新しく起こすと文脈を最初から作り直す）
- **1 ファイル 1 担当。**`src/data/textbook/<章 ID>.ts` と `src/data/questions/<章 ID>.ts` を 1 章 1 ファイルにしているのはこのため
- **書き手・修正役に `npm run check` を走らせない**（並行実行でキャッシュが衝突する）。`npx tsc --noEmit` と `node scripts/check-source.mjs` はよい
- **書き手・修正役に `git stash`・`git checkout`・`git reset` を禁じる。**修正役が `git stash` を使い、
  並行していた別の修正役のファイルが一時的に戻ったことがある（10 月 8 日）
- **報告を鵜呑みにしない。**止まったエージェントは、報告の前にファイルを書き換え終えていることも、
  何も書いていないこともある。**`git status` と `git diff` で確かめる**
- **書き手に問題用紙の PDF を見せるときは、空欄の語の一覧だけをメモさせ、本文はページを見ずに書かせる。**
  確認問題の書き手には PDF を開かせない（`80-questions.md` §3）

### 走らせる順番

1. **教本の残り**（`k4-furnace`、`ea-6`・`ea-9`・`ea-10`〜`ea-12`）… **告示（工場等判断基準）と白書・エネルギー基本計画の数値を
   台帳（`docs/primary-numbers.md`）に足してから。**資源エネルギー庁のサイトはこの PC のコマンドからは 403 を返す
2. **確認問題** … レビューを通った章から。**課目Ⅱ・Ⅲから**始めると、形（式の空欄・連鎖する計算・前置き）の作り方が早く固まる。
   **課目をまたぐテーマ（空気比、蒸気表、冷凍サイクル、判断基準）は本体の章を先に**書き、参照する側の章はあとにする
3. **計算ドリル** … 高圧ガス甲種版の熱力学・流体・伝熱・燃焼のドリルは、章 ID と節 ID を付け替えれば戻せる（`src/data/drills.ts` の注）

## プロンプトに入れてあること（省くと品質が落ちます）

系譜で実際に効いた要素です。**書き換えるときは、この 14 項目を上から順に潰してください。**

1. **読むファイルの指定** … `CLAUDE.md`、`00-common.md`、`01-chapter.md`、出題範囲の資料、**`src/data/textbook/intro.ts`（文体の見本）**
2. **書くファイルの限定** … 「他のファイルは変更しないでください」
3. **節の一覧を表で渡す** … id・タイトル・ねらい・分数・扱う内容。**id を決めて渡さないと勝手な id を作ります**
4. **読者像** … 工場・ビルでエネルギーの管理に携わる技術者。熱力学・流体・伝熱は学校でやったきり、電気を学んだことがない人もいる
5. **この試験の形** … 空欄ごとに解答群から選ぶ。空欄は連鎖する。電卓は √ まで
6. **用語の扱いの型** … 「知っている」と「正確に言える」は違う。現場の語にも 1 行の定義を添える
7. **時点の明記を求める** … **法令は令和 8 年 4 月 1 日時点**（受験案内 注 1）
8. **章の背骨** … その章を貫く一本の考え方
9. **節の骨格** … ざっくり言うと → 本論 → 試験のポイント・よくある勘違い → まとめ → 一問一答。`digest.ts` が拾う書式
10. **一問一答の数の下限**（5 問）
11. **記法の注意** … バックスラッシュ 2 本、ヒアドキュメント禁止、添字は中かっこ、数式の中で記号の波かっこを使わない、強調は行をまたがない
12. **リンクしてよい節 id の全列挙** … **`scripts/check.ts` が `00-common.md` の表を正本として読んでいます**
13. **間違えやすい事実の名指し** … `00-common.md` §8 と `02-dispatch.md`「レビューで出た型」。**名指しした箇所は正しく書けることが多い**
14. **公開問題を写さない** … ECCJ が無断の複製・転写を禁じている。**問題用紙を見ながら書かせない**

## このアプリ固有の注意

1. **法令の数値は台帳を経由させる。**`docs/primary-numbers.md` に無い値は書かせない
2. **★ 数値の周りを、数値と同じ重さで確かめさせる。**台帳の第 1 版は数値が全部合っていたのに、
   **兼任の承認の主体（則 8 条 5 項の括弧書きの読み替え）**を外していた（10 月 9 日に直した）。
   主体・除外・ただし書・括弧書きの読み替え・条番号を名指しで確かめさせる
3. **基準日で切らせる。**e-Gov 法令 API に `asof=2026-04-01` を付けると基準日の版が取れる
4. **工学の物性値・係数は地の文で断定させない。**例題の値は問題文で与える
5. **課目をまたぐテーマは置き場所を守らせる**（`docs/section-plan.md` §3）。本体でない側に同じ説明を書き直させない
6. **4 課目それぞれで配点の 60 % という基準を、どの章でも前提にする。**課目ごとに満点が違う（Ⅰ 200・Ⅱ 200・Ⅲ 110・Ⅳ 280）。
   課目合格（3 年間免除）があるので、「苦手な課目を捨てる」は来年以降に回すことを意味する

### 電卓の制約を、計算問題に反映させること

受験案内 §7：**四則・開平（√）・百分率などだけが使える電卓。関数電卓は禁止。**
**√ は打てますが、指数・対数・三角関数は打てません。**本番は指数・対数に表を付けている。
**指数・対数の値は問題文で与えさせること。**

## 報告を鵜呑みにしないこと

書き手は毎回「事実に自信がない箇所はありません」と書きたがりますが、**そのまま信用してはいけません。**
（そのためレビューのひな形では、この報告を明示的に禁じてあります。）

- 機械的な検査は `npm run check` で必ず確認する
- 内容の正しさは、**書いた人とは別の目**で通しレビューする（根拠は [../../docs/handover.md](../../docs/handover.md) §4）
- **直したら、直した版をもう一度見せる**（`93-review-2nd.md`）

**★ このアプリでも実証済みです。**入門編 4 節を自分で読み返したときの発見は **0 件**、別の目に掛けたら **13 件**。
課目Ⅰの 4 章では、別の目が**台帳の初版の誤り**まで見つけた（兼任の承認に経済産業局長が入ることを落としていた）。
