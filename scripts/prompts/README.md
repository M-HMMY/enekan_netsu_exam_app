## 走らせる順番

**同時 4 本まで。**5 本並べると利用上限に当たります（`docs/handover.md` §3）。

1. **法令の 7 本（`02`〜`08`）は走らせません。**乙種版から引き継いであります
2. **保安管理技術の 7 本（`09`〜`15`）から。**どれから流しても構いません。互いに独立しています
3. **学識は最後。**保安管理技術とテーマが重なるので、あちらが書き上がってから
   「深さが逆になっていないか」を見られる状態にしておくこと
4. **学識の中では、`20-gk-gas` の前に他の化学の章を。**
   `gk-27`（工業的製造法の読み方）が答案の型を作るので、
   **その型が他の節と食い違わないように**、先に他章を見ておくこと

### ★ 順番を守る理由

**`docs/section-plan.md` の「科目をまたいで重なる節」の表**を見てください。
燃焼・爆発、材料と腐食、圧縮機、ポンプ、伝熱・分離、計測機器、漏えい防止は、
**保安管理技術と学識の両方に出ます。**

**保安管理技術は「現場で何が起きるか」、学識は「式を立てて解き、論述する」。**
**深さが逆になると、両方読んだ読者が混乱します。**

**★ 甲種は、保安管理技術も「高度の」です。**
乙種のように「保安管理技術は浅い」とは言えません。**違うのは深さではなく、
問われ方**（現場での判断か、式と論述か）だと考えてください。

## 使い方

**リポジトリの直下で走らせてください。**`--cd` を付けていないので、
**カレントディレクトリがそのまま作業対象**になります
（公開するリポジトリにローカルパスを書かないため、絶対パスを外してあります）。

```bash
codex exec --sandbox workspace-write --color never \
  -o out-02.txt - < scripts/prompts/02-law-what.md
```

- `--sandbox workspace-write` … このリポジトリの中だけ書き換えを許す
- `-o out-02.txt` … **最終メッセージだけ**をファイルに落とす。
  途中の思考ログを読まずに済むので、依頼した側のコンテキストを食わない
- `-` … プロンプトを標準入力から読む（長い日本語をシェルの引用符で壊さないため）

複数を同時に走らせられます。**ただし 1 ファイル 1 担当**にしてください。
`src/data/textbook/<章 ID>.ts` と `src/data/questions/<章 ID>.ts` を
1 章 1 ファイルにするのはこのためです。

**レビューは `--sandbox read-only` で走らせます。**指摘だけさせて、直すのは依頼した側。
書き換えまで任せると、何が変わったのか追えなくなります。

## プロンプトに入れてあること（省くと品質が落ちます）

系譜 7 本で実際に効いた要素です。**書き換えるときは、この 14 項目を上から順に潰してください。**

1. **読むファイルの指定** … `CLAUDE.md`、`00-common.md`、`01-chapter.md`、
   出題範囲の資料、**`src/data/textbook/intro.ts`（文体の見本）**
2. **書くファイルの限定** … 「他のファイルは絶対に変更しないでください」
3. **節の一覧を表で渡す** … id・タイトル・ねらい・分数・扱う内容。
   **id を決めて渡さないと勝手な id を作ります**
4. **読者像** … 一文で言い切り、通じる語と通じない語を具体例で書く
5. **この試験に出ない形を禁じる** … 下の「このアプリ固有の注意」を参照
6. **用語の扱いの型** … このアプリでは「現場の語と法令の語のずれ」
7. **時点の明記を求める** … **基準日がある試験です**（令和 8 年 4 月 1 日）
8. **章の背骨** … その章を貫く一本の考え方。用語がバラバラに見えなくなります
9. **節の骨格** … ざっくり言うと → 本論 → まとめ → quiz。`digest.ts` が拾う書式
10. **一問一答の数の下限** … 用語と数値の取り違えで落とす試験ほど効きます
11. **記法の注意** … バックスラッシュのエスケープ、ヒアドキュメント禁止、
    **`compare` は「1 行 1 セル」で `::` は左右の区切りではない**、図の中で `**` は効かない
12. **リンクしてよい節 id の全列挙** … 省くと存在しない節へリンクして検査に落ちます。
    **★ `scripts/check.ts` が `00-common.md` の表を正本として読んでいます**
13. **間違えやすい事実の名指し** … 先回りで釘を刺す。
    **姉妹アプリでは、名指しした箇所は全章で正しく書けていました**
14. **`npm run check` を実行させない** … 並行実行だとキャッシュが衝突する。
    検査は依頼した側がまとめて 1 回

## このアプリ固有の注意（書き換えるとき必ず入れる）

姉妹アプリの注意（数式を出さない・英略語の 3 点セット）は**この試験には当てはまりません。**
代わりに入れるべきものが 6 つあります。

1. **数値は台帳を経由させる。**`docs/primary-numbers.md` に無い値は書かせない。
   **高圧ガス保安法は数値で適用が分かれます**
2. **★ 数値の周りを、数値と同じ重さで確かめさせる。**
   このアプリで実際に出たのは**そちら**でした。台帳の第 1 版は
   **数値が全部合っていたのに適用範囲と条番号で 7 件**、入門編は
   **数値をひとつも含まない用語の一行定義で 13 件**外しています。
   主体・除外・起点・条番号を名指しで確かめさせること
3. **基準日で切らせる。**「令和 8 年 4 月 1 日現在施行されている法令」。
   **容器保安規則には基準日より後の改正が入っています**
4. **★ 化学と機械を取り違えさせない。**学識だけは完全に別です。
   接頭辞は **`gk-` が化学、`gm-` が機械**。**相互にリンクさせないこと**
   （読者はどちらか一方しか読みません）
5. **科目の線引きを守らせる。**保安管理技術は「現場で何が起きるか」、
   学識は「なぜそうなるか・いくつになるか」
6. **3 科目それぞれで 6 割という基準を、どの章でも前提にする。**
   「法令は捨てて学識で稼ぐ」という戦略が成り立たない試験です

### 電卓の制約を、計算問題に反映させること

受験案内書 Ⅲ-3-③ に**「四則計算のみできる電卓に限り使用を認めます（関数電卓は禁止）」**とあり、
使用可能な機能として**開平計算**が挙がっています。

**ルートは打てますが、対数・指数・三角関数は打てません。**
**対数や指数の値を出させる問題を作らせないこと。**

## Codex の利用上限に注意

姉妹アプリでは、5 本を並行で走らせたとき、3 本が**編集を終えた直後・報告を書く前**に
利用上限に当たりました。ファイルは書き換わっているのに `-o` の出力が空、という状態になります。

- **`-o` の出力が空でも、ファイルは変わっていることがある。**`git diff` で必ず確かめる
- **何が済んで何が残ったかは、こちらで検算する。**
  指示した用語を `grep -c` で数えるのが速いです
- **同時に走らせるのは 4 本まで**にしておくのが無難です

## 報告を鵜呑みにしないこと

Codex は毎回「事実に自信がない箇所はありません」と報告してきますが、
**そのまま信用してはいけません。**
（そのため 90 番・91 番のレビュープロンプトでは、この報告を明示的に禁じてあります。）

- 機械的な検査は `npm run check` で必ず確認する
- 内容の正しさは、**書いた人とは別の目**で通しレビューする。
  省略できる工程ではありません（根拠は [../../docs/handover.md](../../docs/handover.md) §4）
- **直したら、直した版をもう一度見せる。**姉妹アプリでは、1 巡目の指摘を反映して書き直した版に
  2 巡目を掛けたら、**書き直したところから「誤答が実は正しい」が 3 件**出ました

**★ このアプリでも実証済みです。**入門編 4 節を自分で読み返したときの発見は **0 件**、
別の目に掛けたら **13 件**出ました。しかも**数値はひとつも間違っていませんでした。**
