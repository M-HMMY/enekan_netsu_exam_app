# 2 巡目 — 直したところだけを見る（ひな形）

**1 巡目の指摘を反映したあとに掛けるレビューです。**

**なぜ要るか。**系譜では、**1 巡目の修正そのものが新しい誤りを作っていた**箇所が繰り返し見つかっています
（`docs/handover.md` §4）。高圧ガス甲種版の 2 巡目では、**19 件の指摘のうち 14 件が「直し漏れ」**でした。

| 出たもの | 型 |
| --- | --- |
| 本文は直したのに、まとめと一問一答が古いまま | **同じ主張の別の居場所** |
| 確認問題に、その節に無い語を足した | **裏付けのない語を足した** |
| 判定の基準を直したのに、例題の途中の言い回しが古い基準のまま | **直し漏れ** |
| 直した先の語が、教本の語と違う | **語の食い違い** |

**このアプリでも起きています。**

- 台帳の兼任の承認を直したら（2026 年 10 月 9 日）、**同じ主張が教本の比較表・まとめ・よくある勘違い・一問一答の 4 か所**にあった
- 例題の値を直すと、**`scripts/check.ts` の台帳の検査の見逃し一覧**（`allowed`）も直さないと、古い値が残ったまま検査が通る
- 問題文に近い箇所を組み直したら、**本文は離れたのに、試験のポイント・まとめ・一問一答に出題順が残った**（課目Ⅳ、10 月 7 日）

**1 巡目とは見るところが違います。**「全体が正しいか」ではなく、**「この変更が、何かを壊していないか」**を見てください。

**Claude のサブエージェントを新しい文脈で起こし、ファイルを書き換えない役割で走らせてください。**

## 渡すもの

- **差分**（`git diff <1 巡目の前のコミット> -- <対象ファイル>` の出力。渡す側が範囲を指定する）
- **1 巡目の指摘の一覧**と、**採らなかった指摘とその理由**
- 変更後のファイル（リポジトリの現在の中身）、`CLAUDE.md`、`docs/primary-numbers.md`

## 何を見るか（この順に）

### 1. ★ その変更が、新しい誤りを作っていないか（最優先）

- **足した条件が、別の正しいことを否定していないか**（「理想気体なら」と限定したせいで、実在気体でも成り立つ話まで狭めた）
- **「原則として」「場合がある」と弱めたせいで、例外のないことまで曖昧にしていないか**
- **足した文が、同じ節の別の段落・別の章と矛盾していないか**
- **作り直した例題の数値を、自分で検算する**（Python で）。合計と内訳、丸めの前と後
- **言い換えた法令の記述**：主体・除外・ただし書が、言い換えの途中で落ちていないか（条文に当たる）

### 2. ★ 直し漏れ — 同じ主張の別の居場所（いちばん多い）

**1 つの主張は、1 つの節の中に 6 つの居場所を持ちます。**

```
本文 ／ 表 ／ 試験のポイント ／ よくある勘違い ／ この節のまとめ ／ 一問一答
```

**さらにその外側に、ほかの章・確認問題・前置き・計算ドリル・体験ウィジェット・台帳・検査の見逃し一覧・執筆プロンプトがあります。**
**執筆プロンプトを直し忘れると、書き直したときに同じ誤りが戻ります。**

```
node scripts/echoes.mjs 空気比            … その語がどこに何回あるかを、居場所つきで出す
node scripts/echoes.mjs 承認 局長          … すべてを含む行だけ
node scripts/terms.mjs                    … 確認問題が使っていて、教本に無い語を挙げる
```

- **直した語・数値・言い回しが、ファイルの中に何か所あるか数える**
- **例題の途中の言い回し**が、直した判定基準と食い違っていないか
- **課目をまたぐテーマ**（`docs/section-plan.md` §3）の、本体でない側の章に古い言い方が残っていないか

### 3. ★ 確認問題を直した場合

- **`answer` が、直した後の記述の正誤・計算の値と合っているか**
- **解説の「①は正しい」「②は誤り」が、直した後の記述と合っているか**
- **選択肢の中に、直した後の正解が実際にあるか。**数値なら、直した後の値にいちばん近いのが正解の選択肢か
- **前置きを直したなら、その前置きを使う問題をすべて解き直す**（1 問だけ直して、ほかの問題の答えが変わっていないか）
- **足した記述が、その問の `sectionId` の節に裏付けを持っているか**
- 記述の長さが不ぞろいになり、**読まずに選べる**ようになっていないか

### 4. ★ 教本を直した場合

- **節の画面の字数**（`npm run dump <節 id>`）が 2,500 字を切っていないか（4,000 字超は止めない目安）
- **`**` の開きと閉じが同じ行にある**か、数式のバックスラッシュが 2 本か、添字が中かっこで包まれているか
- **張ったリンクの節 ID が実在する**か
- 足した内容が、**その節の担当範囲**（`docs/section-plan.md` §5）を越えていないか
- **組み直した箇所が、また問題文に近づいていないか**（並べる順・例示・場面）

### 5. ★ 指摘を採らなかった判断が妥当か

1 巡目の指摘のうち、依頼した側が採らなかったものがあれば、**その理由が成り立つか**を見てください。

## 報告の形

```
### 【重さ】 対象（ファイル:行）— 一行の要約

- **どう直したか**：（差分のどの行か）
- **何が問題か**：（★ 新しい誤りか、直し漏れか、どちらかを明示する）
- **正しくは**：
- **根拠**：（条・項・号、一次資料、検算の値、またはファイル名と行）
```

| 重さ | 何か |
| --- | --- |
| **重** | **直したことで新しい誤りができた。**または、直した主張と正面から矛盾する記述が残っている |
| **中** | 直し漏れ。1 か所だけ古い言い方が残っている |
| **軽** | 言い回し、長さ、リンク |

**最後に、次の 4 つを必ず書いてください。**

1. **差分のすべての変更を見たか**（見ていないものは挙げる）
2. **確かめたが問題が無かった変更**
3. **資料からは確かめられなかったもの**
4. **★ あなたが自信を持てない指摘**

**「1 巡目の修正はすべて妥当です」だけの報告は受け付けません。4 が空の報告も受け付けません。**
