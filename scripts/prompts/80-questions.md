# 確認問題を書かせるプロンプト（章ごとに使い回す）

**この文書はひな形です。**`【章 ID】``【章の名前】``【問題数】``【節 ID の範囲】``【export 名】` を
実際の値に置き換えて、Claude のサブエージェントに渡してください（渡し方は `02-dispatch.md` と同じ。
同時 4 本まで、終わったら別の目のレビュー `91-review-questions.md`）。

**教本が書き上がり、別の目のレビューを通った章からでないと使えません。**問題は節にひも付けます。

（2026 年 10 月 10 日に、高圧ガス甲種版のひな形からこの試験向けに書き換えた。）

---

## 0. この試験の確認問題の形（**決定済み。`CLAUDE.md`「確認問題の形」**）

**1 問 ＝ 本番の空欄 1 つ。**本番の大問は、1 つのテーマの文章に空欄が 10〜20 個並び、
**空欄ごとに専用の解答群（2〜20 個）が付いて、1 つずつマークする**形です（`docs/public-questions.md` §2）。
このアプリは、その最小単位「前置きの文脈 ＋ 空欄 1 つ ＋ その空欄の解答群」を 1 問にします。

- **選択肢の数は空欄の種類で決める。5 に揃えないこと**（下の §3）
- **大問の設定は前置き（`Passage`）に 1 回だけ書き、問題から `passage` で指す**
- **前の空欄の答えは前置きに書かず、問題文の側で与える**（「理論空気量を 10.5 m³N/kg とすると」）。
  復習キューは問題をばらばらの順で出すので、前の問題を解いた前提にできない
- **模試の画面には「本番の問題の形ではない」と書いてある**（大問の連鎖と配点の重みを再現しないため）。消さない

## 4. 書くファイル

**`src/data/questions/【章 ID】.ts` だけ**を書いてください。**他のファイルは変更しないこと。**
`src/data/questions/index.ts` と `passages.ts` への登録は依頼した側がやります。

```ts
import type { Passage, Question } from '../../types';

/** この章の大問の前置き。依頼した側が passages.ts に登録する */
export const 【export 名】Passages: Passage[] = [
  {
    id: '【章 ID】-p1',
    categoryId: '【章 ID】',
    body: 'メタン 85 %、エタン 10 %、窒素 5 %（体積）の都市ガスを、空気比 1.2 で完全燃焼させる。…',
  },
];

export const 【export 名】: Question[] = [
  {
    id: '【章 ID】-1',
    categoryId: '【章 ID】',
    sectionId: 'fc-14',
    passage: '【章 ID】-p1',
    question: 'この燃料 1 m³N の理論空気量に最も近い値はどれか。',
    choices: ['8.6 m³N', '9.2 m³N', '9.8 m³N', '10.4 m³N', '11.0 m³N'],
    answer: 2,
    explanation: '…',
    level: 2,
  },
];
```

- **`sectionId` は必ず付けること。**解説から教本へ戻る導線と、節ごとの出題に使います
- **`id` は `【章 ID】-1` から連番。前置きは `【章 ID】-p1` から**
- **`level` は 1（易）〜3（難）。**2 を中心に散らす
- **`answer` は 0 始まりの添字**（0 ＝ ア）。複数選ぶ問題だけ昇順の配列（下の §5）
- 前置きは **600 字まで**、問題文は **200 字まで**が目安（300 字を超えると検査が止める）。
  **前置きを使う問題が 1 問だけなら、前置きは作らずに問題文へ入れる**

## 5. ★ 空欄の種類と、解答群の作り方

**本番の解答群の数に合わせます。**章の中の種類の比率は、担当の大問の本番の比率に寄せること（`public-questions.md` §2・§3）。

| 種類 | 解答群 | 書き方 |
| --- | --- | --- |
| **語句** | **4**（いちばん多い） | 文の中の空欄を `[ ? ]` で示し、「[ ? ] に当てはまる語はどれか」。誤答は**同じ範ちゅうの語**（制御方式なら制御方式） |
| **数値** | **5** | 「最も近い値はどれか」。**小さい順に並べる**。単位を選択肢に付ける |
| **式** | **4** | 選択肢に `$...$` で式を書ける（画面が行内数式として描く）。誤答は**ありがちな立て違い**（逆数、2 乗の落とし、出入りの符号） |
| **大小・向きの比較** | **2〜3** | 「大きくなる／小さくなる／変わらない」。**章の中で 2 択は 2 割まで**（検査が注意を出す） |
| **組合せ「全て挙げると」** | **7** | 本文に ①〜③ を行頭に並べ、選択肢は**本番と同じ 7 つをこの順に**：`'①', '②', '③', '①と②', '①と③', '②と③', '①と②と③'`。検査が順を見る |
| **組合せ「二つ挙げると」** | **6** | ①〜④ を並べ、2 つ組 6 つを若い順に |
| **明らかに間違っているもの** | **6** 前後 | 記述を ①〜⑥ のように並べ、**「2 つ選びなさい」と問題文に必ず書く**。`answer` は昇順の配列 `[1, 4]`。**課目Ⅲ問題 9（`k3-burn`）で 3 年連続** |
| **共有の語群** | **6〜11** | 本番は数個の空欄で 1 つの語群を共有する。1 問に大きめの語群を付けてよいが、**使わない語も同じ範ちゅうに揃える** |

**課目ごとの傾向（本番の比率に寄せるための目安）：**

- **`k1-law`**：条文の当てはめの語句・数値と、**「全て挙げると」の組合せが毎年 4〜5 空欄**。数値は台帳の値だけ
- **`k1-tech`**：**課目Ⅰ問題 3 は 17 個ほどの独立した小問**（1 小問 1 空欄・4〜5 択）。前置きはほとんど要らない
- **`k3-calc`**：**一本の計算が連鎖する**。前置き 1〜2 つに 15 問をぶら下げ、前の答えは問題文で与える
- **課目Ⅱ・Ⅳ**：式を導く空欄 → その式で数値を出す空欄、の並び。**式の空欄と数値の空欄を両方入れる**

### 組合せ・誤り選びの記述の書き方

- **記述は問題文の中に、行頭の丸数字で並べる**（`\n①　…\n②　…`）。**選択肢の丸数字は本文にあるものだけ**（検査が見る）
- **1 つの記述で 1 つのことだけを言う。**2 つ言うと正誤が定まらない
- **正しい記述と誤りの記述を同じ密度で書く。**正しいものだけ長いと読まずに当てられる
- **「必ず」「すべて」「常に」を誤り専用にしない。**正しく言い切れる場面では正しい記述にも使う
- **「全て挙げると」の正解が「①と②と③」になる問題は、3 割まで**（検査が注意を出す）。要素数も散らす
- **誤りの作り方**（この試験で効く型）：

| 型 | 例 |
| --- | --- |
| **主体を入れ替える** | 届出先（経済産業大臣／主務大臣）、選任するのは誰か、承認するのは誰か |
| **除外・限定を落とす／足す** | 「〜を除く」「〜に限る」「ただし」。**系譜で外したのは毎回ここ** |
| **基準を入れ替える** | 高発熱量と低発熱量、乾きと湿り、体積基準と質量基準、ゲージ圧と絶対圧、入熱基準と出熱基準 |
| **向きを入れ替える** | 大きくなる／小さくなる、上流／下流、正／逆動作 |
| **隣の機器・方式の性質を持ってくる** | 吸収式の性質を圧縮式に、比例動作の性質を積分動作に |
| **条件を落とす** | 「理想気体では」「定常で」「同じ流量で」を外すと、正しい記述が言い過ぎになる |

## 6. ★ 公開問題（©ECCJ）を写さない

**ECCJ の過去問ページに「全部又は一部を無断で複製・転写することを固く禁じます」とあります。**
**高圧ガス甲種版では、公開問題とほぼ同文の記述が確認問題に系統的に入っていて、公開後に見つかりました。**

- **前置きの設定（燃料の組成、サイクルの温度・圧力、事業者の事例、機器の仕様）は、すべて自前で作る。**
  本番の数値の組を使わない。燃料の種類や場面も、本番と違うものを選ぶ
- **本番の空欄の文をなぞって、空欄の位置だけ変える書き方をしない。**
  語尾を変える・一文を分ける・条件句を削るだけでは、自前で書き起こしたことになりません
- **`public-questions.md` §7 の記述（要旨）を、そのまま ①〜③ の記述に使わない。**仕組みや因果から別の切り口で書く。
  **§7 で「誤」とされた記述を、正しい記述として使わない**
- **問う語が本番の空欄と同じなのはかまわない**（試験範囲の語なので）。**場面・切り口・並べる順を自分で選ぶ**こと
- **章の問題を、本番の空欄の出題順に並べない**

## 7. 数値と計算

### 法令の数値（`k1-law`、`ea-6`・`ea-9`）

1. **`docs/primary-numbers.md` に載っている値だけを使う**（誤答側の数値も）
2. **台帳に無い数値が要る問題は書かずに、報告に挙げる**
3. **要件を引くなら全部並べる。**1 つ落とすと、誤答のつもりが正答になる
4. **主体・除外・ただし書・括弧書きの読み替え**を、数値と同じ重さで確かめる
   （兼任の承認に経済産業局長も入る、という台帳の初版の誤りは、則 8 条 5 項の括弧書きの読み替えだった。§4）

### 工学の数値

- **物性値・係数は問題文か前置きで与える。**地の文で断定した値を前提にしない
- **計算は必ず Python で検算する。**途中の値を丸めたときに、どの選択肢に近くなるかも確かめる
  （本番は「最も近い値」。**丸め方で正答が隣の選択肢に移らないこと**）
- **電卓は四則と √ まで**（関数電卓は禁止）。**指数・対数・三角関数の値が要るなら、問題文で与える**
  （本番は表を付ける：「$e^{0.5}=1.649$ とする」）
- **誤答の数値は「ありがちな間違え方」で作る**：℃ のまま入れた、ゲージ圧のまま入れた、高・低発熱量を取り違えた、
  乾き・湿りを取り違えた、単位を kJ と MJ で 1,000 倍ずらした、2 乗・平方根を落とした。**ただの倍数を並べない**
- **数値の選択肢は小さい順に並べる。**正解の位置が章の中で真ん中ばかりにならないよう、選択肢の幅をずらして散らす
- **選択肢どうしの間隔は、検算の丸めの幅より十分大きくする**

## 8. 守ること

### 問題文

- **教本を読んでいなくても、問題文（と前置き）だけで何を問われているか分かること**
- **「本文で述べた」「この節の」「前問で求めた」のような参照を書かない**（模試は順不同で出す。検査が弾く）
- **条件を問題文に必ず書く。**理想気体か、定常か、どちらの基準の発熱量か、乾きか湿りか、ゲージか絶対か
- **法令の問題は、基準日（令和 8 年 4 月 1 日時点）を問題文に書かなくてよい**（画面が `LAW_PREAMBLE` を自動で添える）。
  法・令・則の略記は本番と同じに使ってよい

### 解説

- **正解の理由と、誤答が「なぜ違うか」を書く。**組合せと誤り選びは、**記述 1 つずつ**「①は正しい。…」「②は誤り。…」
- **計算は式・代入・単位付きの値を途中まで書く**（教本の「計算の骨組み」と同じ）
- **教本の本文と食い違わないこと。**教本と違う語・違う記号を使わない
- **条番号を書くなら条文で確かめる**（e-Gov 法令 API に `asof=2026-04-01` を付けると基準日の版が取れる）
- **「〜と覚えましょう」で終わらせない。**理由を書く

### 章をまたいだ重複

- **課目をまたいで同じテーマがある**（空気比は `fc-16`〜`fc-19` と `ea-16` と `hu-17`、蒸気表は `tf-12` と `hu-17`、
  冷凍サイクルは `tf-16` と `hu-37`。置き場所は `docs/section-plan.md` §3）。**同じ問題を両方に書かない**
- **問題は本体の節にひも付ける。**参照するだけの側の章には、その章の切り口（実務・機器）で書く
- `npm run check` が、章をまたいだ似た問題に注意を出す

## 9. 記法

問題文・前置き・解説は Markdown（教本と同じ自前の記法）、選択肢は**文字と `$...$` の数式だけ**です。

| 書きたいもの | ファイルに書く形 |
| --- | --- |
| 改行 | `\n`（**文字列の中なのでこれでよい**） |
| 数式の `\frac` | **`\\frac`**（バックスラッシュ 2 本） |
| 細空き | **`\\,`**（1 本だと画面に読点が出る） |
| 添字・アクセント | 中かっこで包む：`T_{\\mathrm{in}}`、`\\dot{m}` |

- **数式の中で記号の波かっこを使わない**（描画検査がエラーにする）。**`{,}` も使わない**
- **強調 `**` は行をまたがない。閉じ忘れない**
- **bash のヒアドキュメントで書かない。**バックスラッシュが落ちる。Write／Edit を使う

## 10. やってはいけないこと

1. **公開問題の原文・設定・数値の組を写さないこと**（§6）。**問題用紙の PDF を開かないこと**
2. **指定されたファイル以外を変更しないこと**
3. **`npm run check` を実行しないこと**（並行実行でキャッシュが衝突する）。`npx tsc --noEmit` と
   `node scripts/check-source.mjs` は走らせてよい
4. **`git stash`・`git checkout`・`git reset` を使わないこと**（並行して動く別の書き手のファイルまで戻る）
5. **「事実に自信がない箇所はありません」と報告しないこと**

## 11. 報告

日本語で、次の形で。

1. **書いた問題の数**と、**節ごとの内訳**、前置きの数
2. **空欄の種類ごとの数**（語句・数値・式・比較・組合せ・誤り選び）と、**解答群の数ごとの数**（2 択が何問か）
3. **計算問題の検算**（Python で出した値と、正解の選択肢との差）
4. **台帳に無くて書けなかった数値・問題**
5. **★ 自信がない箇所**（正解が 1 つに定まるか怪しいもの、条番号、適用範囲、本番の文に近づいたかもしれないもの）
6. **他の章と重なりそうな問題**と、**教本に書き足すべきだと思った点**（問題を作るうえで本文に足りなかったこと）

**5 が空の報告は受け付けません。**必ず 1 つ以上挙げてください。
