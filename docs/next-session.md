## 2. 作業の回し方（課目Ⅱで回した手順）

**codex は使わない。執筆もレビューも Claude のサブエージェントに任せる**（`CLAUDE.md`「内容の正しさ」）。

1. **書かせる**：`scripts/prompts/02-dispatch.md` の「書き手の依頼文」に、担当章と「章ごとの注意」を足して渡す。
   **同時 4 本まで。**書き手は章ごとの指示書 `scripts/prompts/10-【章 ID】.md` を自分で作ってから本文を書く
2. **登録する**：`src/data/textbook/index.ts` に import と `SECTIONS` への追加（書き手は触らない）
3. **検査する**：`npx tsc --noEmit`、`npm run check`、`npm run build`。エラー 0、「うち長さ以外」は未着手の節へのリンクだけ
4. **コミットする**（「別の目のレビューはこれから」と書く）。**push はまだしない**
5. **レビューさせる**：`02-dispatch.md` の「レビュアーの依頼文」で、**書いた本人とは別のサブエージェント**を 2 本。
   書き手が「自信がない」と挙げた点を依頼の末尾に列挙して判定させる
6. **直させる**：指摘を、担当ファイルを分けた修正役 2 本に渡す（**同じファイルを 2 本に触らせない**）。
   担当外で見つかった点（共通プロンプト・section-plan など）は自分で直す
7. **検査 → コミット → push → 公開ページの `index-*.js` が `dist/` と一致するかで反映を確かめる**
   （GitHub の API は認証なしだと 1 時間 60 回で止まる）

**★ 利用上限に当たったら**：止まったエージェントには `SendMessage` で「git diff で現状を確かめて続きから」と送れば再開できる
（同じセッションのうちなら）。セッションをまたいだら、残ったファイルを確かめてから新しく起こす。

## 5. このセッションで直した、ほかのリポジトリにも効くこと

- **細空き `\,` は 2 本（`\\,`）**。1 本だと TypeScript が食って画面に読点が出る（`check-source.mjs` が鳴る）
- **アクセントと添字の命令は中かっこで包む**（`\\dot{m}`、`T_{\\infty}`）。中かっこなしは描画が崩れる。
  **`check-source.mjs` が弾く**ようにした。高圧ガス甲種・乙種の公開中の教本にも同じ崩れがあり、直してある
- **数式の中で記号の波かっこを出さない**（`\\{`）。`render-check.tsx` が崩れとみなしてエラーにするので角かっこにする
- **ECCJ の問題用紙の PDF は文字がアウトライン化されていて、公開問題との機械照合ができない**
  （高圧ガス甲種版には `scripts/public-overlap.mjs` があるが、ここでは作れない）。書き手への指示とレビューで守る

- **書き手に問題用紙の PDF を見せると、「問われたのに書かれていない」は減るが、問題文の並び・例示・場面まで写る。**
  課目Ⅳの計測・制御・原動機・熱交換器は、別の目の確かめを 3 回、組み直しを 3 回した。
  **本文を組み直しても、試験のポイント・まとめ・一問一答に空欄の答えが出題順に残る**型が最後まで残った。
  依頼文（`02-dispatch.md`）に「PDF は空欄の語の一覧だけメモし、本文はページを見ずに書く」
  「一問一答は空欄をそのまま問わない」「ポイントとまとめは本文の軸から」を足してある。**次の章（工業炉・課目Ⅰ）は最初からこれで書かせること**
- **問題に無い自前の内容（実務・式・数値例・例題の値）で厚くするのがいちばん効いた。**表への並べ替え・縮約では離れない
- `check-source.mjs` に足した検査：flow 図の行頭の `->`、節の題のバッククォート、箇条が 1 行につながる（句点の直後の「- 」）
- 修正役が `git stash` を使うと、並行している別の修正役のファイルまで一時的に戻る。**依頼文で `git stash` を禁じること**
